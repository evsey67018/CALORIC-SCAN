# Caloric Scan

Сфотографируй тарелку — страница найдёт ингредиенты и прикинет калории. Это статический сайт: свои модели работают в браузере, сервера и чужого ИИ нет. Снимок никуда не отправляется.

Сайт: https://evsey67018.github.io/CALORIC-SCAN/

## Как это работает

Одна кнопка «Добавить фото» — обычный `<input type="file" accept="image/*">` без `capture`, поэтому телефон сам предлагает снять кадр или взять его из галереи. На компьютере фото можно перетащить на ту же область.

Дальше в браузере две головы одной и той же сети MobileNetV2:

1. **Ингредиенты.** Декодер сегментации, обученный на [FoodSeg103](https://github.com/LARC-CMU-SMU/FoodSeg103-Benchmark-v1) (103 класса: рис, курица, помидор, хлеб и остальные). Маска рисуется поверх фото. Связные куски одного класса считаются отдельно: «2 кусочка курицы», «3 ломтика помидора».
2. **Название блюда.** Голова Food-101 из первой версии. Если она уверена хотя бы на 40%, под фото будет «Похоже на: …». Калории от этого названия не зависят.

Питание считается только по ингредиентам. Граммы слайдером не задаются.

## Как получаются граммы

Тарелка принимается за круг около **26 см**. Если еда занимает почти весь кадр, диаметром считается короткая сторона снимка. Иначе берётся рамка еды с небольшим запасом. Дальше:

граммы ≈ (площадь маски в см²) × (граммы на см²)

«Граммы на см²» — это обычная толщина продукта на тарелке, умноженная на плотность. Рис примерно 1,1 г/см², курица около 1,9, соус 0,35, лист салата 0,2. Таблица лежит в `data/ingredients.json`. Это не весы: соус, ракурс и обрезка кадра легко сдвигают цифру в разы.

Ккал, белки, жиры и углеводы — на 100 г по типичным карточкам USDA FoodData Central, затем умножаются на оценённые граммы.

## Точность

Обе головы стартуют с чекпоинта v1: тот же MobileNetV2, не обучение с нуля. Голова блюда пересчитана на входе 224×224 (линейный слой поверх замороженного backbone). Официальный test Food-101, все **25 250** фото, в обучении не участвовал:

| | было (160px, v1) | стало (224px, голова) |
| --- | --- | --- |
| top-1 | 61,1% (0,6106) | **64,1%** (0,6407) |
| top-5 | 85,5% (0,8546) | **87,1%** (0,8705) |

Память блюд — банк прототипов в том же признаковом пространстве (PCA 64, int8, чанки). kNN по официальному test Food-101 сам по себе **35,1%**: четырёх прототипов на класс мало против линейной головы. Смешивание, подобранное на внутренней проверке, на тесте дало **62,2%** — хуже одной головы, потому что иногда подменяет уверенный класс Food-101. На 458 отложенных фото длинного хвоста (подпись = поисковый запрос, метки шумные) top-1 прототипа **62,9%**. Каталог имён — 10 000 блюд (Food-101, Food2K, Open Food Facts), с ккал/100 г из USDA, ручной таблицы или оценки по ближайшей категории.

Сегментация на validation FoodSeg103, **2 135** фото, среднее IoU по 103 пищевым классам:

- mIoU: **13,2%** (попытка декодера DeepLab на средних картах дала 10,8% и в сайт не пошла)
- точность пикселя: **60,8%**

В браузере мелкие и неуверенные маски отсекаются, а «пицца» как ингредиент остаётся только если блюдо само похоже на пиццу. Модель блюда около **4,7 МБ**, ингредиенты **4,8 МБ**, первый чанк памяти вместе с индексом около **2 МБ**. Следующие чанки догружаются после открытия страницы.

## Как переобучить

Food-101 и FoodSeg103 в git не входят.

```bash
pip install -r training/requirements.txt
# чекпоинт v1: training/train.py пишет /tmp/caloric_head.weights.h5
python training/train_seg.py --weights /tmp/caloric_head.weights.h5 --epochs 6 --finetune-epochs 1
python training/build_ingredients.py
```

Подробности по Food-101 — в [training/README.md](training/README.md). `training/train_seg.py` не даст закоммитить голову блюда, если top-1 на официальном тесте уйдёт ниже 0,6106.

## Аккаунт и подписка

Бесплатно — **3 скана в день**. Премиум снимает лимит. Оплата только через СБП, картой платить нельзя, автопродления нет: **199 ₽ = 30 дней**, **1299 ₽ = 365 дней**. Год на 46% дешевле, чем 12 × 199 ₽ (2388 ₽). Новый срок прибавляется к `max(сейчас, premium_until)`, так что оплата заранее не сжигает оставшиеся дни. За три дня до конца на сканере появляется «Подписка заканчивается через N дней — продлить».

Пока в `config.js` стоят заглушки `YOUR_…`, вход не нужен: счётчик живёт в `localStorage` и обнуляется по московским суткам. Надпись «Осталось N из 3 сканов сегодня» видна над кнопкой фото. На четвёртом скане открывается окно с двумя суммами и кнопкой «Оплатить по СБП». Без платёжного воркера она пишет «Оплата скоро будет доступна».

Вход уже смотрит на проект Supabase. В `config.js` лежит публичный publishable-ключ (`sb_publishable_…`), его понимает supabase-js 2.119. Пароля нет: «Войти» → почта → «Получить код» → 6 цифр из письма → «Войти». Если Supabase или лимит не отвечают, скан всё равно запускается. Платёжный адрес воркера пока заглушка.

### 1. Supabase

1. Создай проект на [supabase.com](https://supabase.com).
2. Authentication → Providers → Email: включи email, magic link / OTP. Шаблоны писем можно оставить стандартными: в письме есть и ссылка, и код.
3. Authentication → URL Configuration → Site URL: `https://evsey67018.github.io/CALORIC-SCAN/`. В Redirect URLs добавь тот же адрес и, если проверяешь локально, `http://127.0.0.1:8765/`.
4. SQL Editor → New query: вставь целиком `supabase/schema.sql` и нажми Run.
5. Project Settings → API: скопируй Project URL и `anon` `public` key. `service_role` на сайт не клади.
6. В `config.js` замени заглушки:

```js
window.CALORIC_CONFIG = {
  supabaseUrl: "https://xxxx.supabase.co",
  supabaseAnonKey: "eyJ...",
  paymentWorkerUrl: "https://caloric-scan-pay.xxxx.workers.dev",
};
```

Закоммить `config.js` с anon key можно: этот ключ и так виден в браузере. Лимит после входа считает функция `consume_scan` в базе, пользователь сам `plan` и `premium_until` не меняет.

### 2. Cloudflare Worker

Из папки `worker/`:

```bash
npx wrangler login
npx wrangler secret put SUPABASE_URL
npx wrangler secret put SUPABASE_ANON_KEY
npx wrangler secret put SUPABASE_SERVICE_ROLE_KEY
npx wrangler secret put YOOKASSA_SHOP_ID
npx wrangler secret put YOOKASSA_SECRET_KEY
npx wrangler deploy
```

`ALLOWED_ORIGINS` уже в `worker/wrangler.toml`. Локально секреты кладут в `worker/.dev.vars` (образец — `worker/.dev.vars.example`); этот файл в git не входит.

Адрес воркера впиши в `config.js` → `paymentWorkerUrl`.

### 3. ЮKassa

1. В кабинете ЮKassa возьми `shopId` и секретный ключ. Это `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` выше.
2. HTTP-уведомления направь на `https://<воркер>/webhook` (событие `payment.succeeded`).
3. В кабинете ЮKassa должен быть включён способ оплаты СБП. Сайт вызывает `POST /create-payment` с планом `month` (30 дней, 199 ₽) или `year` (365 дней, 1299 ₽). Воркер создаёт платёж только с `payment_method_data.type = sbp`, без `save_payment_method`, и возвращает `confirmation_url`.
4. В вебхуке статус из тела уведомления не используется. Воркер ещё раз запрашивает платёж у API ЮKassa. Премиум ставится, только если платёж `succeeded`, способ оплаты именно `sbp`, сумма совпала с тарифом и запись есть в таблице `payments`. К `premium_until` прибавляется 30 или 365 дней от `max(сейчас, текущий premium_until)`.

Пока ключей нет, воркер отвечает 501, а кнопка показывает «Оплата скоро будет доступна».

## Ограничения

- 103 ингредиента FoodSeg103, не вся еда. mIoU 13% — это грубая маска: лишний класс (на фото риса с курицей вылез «картофель») и пропуски бывают часто.
- Граммы — площадь на сетке 56×56 и средняя толщина, не порция с весов.
- Название блюда показывается только при уверенности от 40%. На смешанной тарелке его часто нет, и это нормально: калории всё равно берутся из ингредиентов.
