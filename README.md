# Caloric Scan

Сфоткай еду — страница скажет, что на тарелке, и посчитает калории. Это статический сайт: своя нейросеть работает в браузере, сервера и стороннего ИИ нет. Фото никуда не уходит.

Сайт: https://evsey67018.github.io/CALORIC-SCAN/

## Как это работает

1. Ты загружаешь снимок, перетаскиваешь файл или снимаешь камерой («Сфоткать»).
2. В браузере TensorFlow.js прогоняет фото через модель из папки `model/`. Это MobileNetV2: старт с открытых весов ImageNet, затем дообучение на [Food-101](https://data.vision.ee.ethz.ch/cvl/datasets_extra/food-101/) (101 блюдо). В репозитории лежит граф TFJS с весами float16, чтобы файл оставался небольшим. Повторно модель берётся из IndexedDB.
3. Под фото — карточка: русское и английское имя, уверенность, три похожих варианта (их можно нажать и поправить ответ), порция в граммах и числа: калории, белки, жиры, углеводы, плюс клетчатка и сахар, если они есть. Кольцо показывает, какая доля энергии пришла из белков, жиров и углеводов. Порцию можно двигать — цифры пересчитываются сразу.
4. «Добавить в дневник» пишет порцию в `localStorage`. Видны итог за сегодня и полоска цели (по умолчанию 2000 ккал, цель можно поменять).

Если модель уверена меньше чем на 30%, страница прямо просит выбрать вариант из тройки или найти блюдо в списке всех 101. Тот же список открывается кнопкой «Не то блюдо?».

Калории приблизительные: это средний состав на 100 г, а не лабораторный разбор именно твоего рецепта.

## Точность

Модель: MobileNetV2, картинка 160×160, старт с весов ImageNet. Голову классификатора учили на признаках **73 730** обучающих фото (21 эпоха, ранняя остановка). Потом две эпохи дообучали последние блоки сети (`block_15`, `block_16`, `Conv_1`) с learning rate 1e-4: на обучении top-1 вырос до 76%, но проверка просела с 58% до 27%, поэтому в сайт положен первый вариант — голова на замороженном backbone. Веса при дообучении реально менялись (сумма модулей ядра `block_15_expand` сдвинулась на 37,8), просто этот чекпоинт хуже обобщает.

Замер на официальном тесте Food-101, **все 25 250 фото**, в обучении их не было:

- top-1: **61,1%**
- top-5: **85,5%**

Внутренняя проверка, по которой выбирали чекпоинт (20 фото каждого класса из train, 2020 снимков): top-1 57,6%, top-5 80,7%.

Файл модели — граф TensorFlow.js, веса float16, **4,6 МБ**.

Сеть путает похожие блюда: яблочный пирог около 27% top-1, хлебный пудинг 28%, стейк 31% (рядом филе и прайм-риб). Увереннее на эдамаме (96%), макарунах (90%), кисло-остром супе (87%). Поэтому под ответом всегда есть три других варианта и ручной список.

## Датасет

[Food-101](https://data.vision.ee.ethz.ch/cvl/datasets_extra/food-101/) (ETH Zürich): 101 класс, 750 обучающих и 250 тестовых фото на класс. В git архив не входит. Русские названия всех классов — в `data/labels.json`, порядок совпадает с `training/food101_classes.txt`.

## Откуда калории

`data/nutrition.json` — энергия и БЖУ **на 100 г**, плюс типичная порция в граммах.

Источник — USDA FoodData Central, типы SR Legacy и Survey (FNDDS). Скрипт `training/build_nutrition.py` ищет карточку блюда и записывает `fdc_id`. Если готового блюда в базе нет или ответ API не проходит проверку, стоит пометка `curated USDA reference`: это ручная сводка по близким справочным продуктам USDA, не «красивые» нули. Карточка на сайте всё равно округляет порцию и не знает соус, масло и размер куска.

## Как переобучить

Коротко: скачать Food-101, поставить зависимости из `training/requirements.txt`, запустить `python training/train.py --data /путь/к/food-101 --out model`. Пошагово — в [training/README.md](training/README.md).

## Структура

- `index.html`, `css/styles.css`, `js/app.js` — страница
- `model/` — графовая модель TFJS
- `data/labels.json`, `data/nutrition.json` — имена и калорийность
- `training/` — обучение, конвертер, сбор таблицы
- `.nojekyll` — чтобы GitHub Pages отдал `model/` как есть

Страница рассчитана на адрес с подпутём `/CALORIC-SCAN/`: все пути относительные. TensorFlow.js подключается с jsDelivr, шрифты Unbounded и Manrope — с Google Fonts.
