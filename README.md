# Caloric Scan

Сфотографируй тарелку — страница найдёт ингредиенты и прикинет калории. Это статический сайт: свои модели работают в браузере, сервера и чужого ИИ нет. Снимок никуда не отправляется.

Сайт: https://evsey67018.github.io/CALORIC-SCAN/

## Как это работает

Одна кнопка «Добавить фото» — обычный `<input type="file" accept="image/*">` без `capture`, поэтому телефон сам предлагает снять кадр или взять его из галереи. На компьютере фото можно перетащить на ту же область.

Дальше в браузере две головы одной и той же сети MobileNetV2:

1. **Ингредиенты.** Декодер сегментации, обученный на [FoodSeg103](https://github.com/LARC-CMU-SMU/FoodSeg103-Benchmark-v1) (103 класса: рис, курица, помидор, хлеб и остальные). Маска рисуется поверх фото. Связные куски одного класса считаются отдельно: «2 кусочка курицы», «3 ломтика помидора».
2. **Название блюда.** Голова Food-101 из первой версии. Если она уверена хотя бы на 40%, под фото будет «Похоже на: …». Калории от этого названия не зависят.

Питание считается только по ингредиентам. Граммы слайдером не задаются.

## Как получаются граммы

Тарелка принимается за круг около **26 см**. Если еда занимает почти весь кадр, диаметром считается короткая сторона снимка. Иначе берётся рамка еды с небольшим запасом. Дальше:

граммы ≈ (площадь маски в см²) × (граммы на см²)

«Граммы на см²» — это обычная толщина продукта на тарелке, умноженная на плотность. Рис примерно 1,1 г/см², курица около 1,9, соус 0,35, лист салата 0,2. Таблица лежит в `data/ingredients.json`. Это не весы: соус, ракурс и обрезка кадра легко сдвигают цифру в разы.

Ккал, белки, жиры и углеводы — на 100 г по типичным карточкам USDA FoodData Central, затем умножаются на оценённые граммы.

## Точность

Обе головы стартуют с уже обученного чекпоинта v1 (MobileNetV2 на Food-101, не с нуля и не с голого ImageNet). Ранние блоки при обучении сегментации были заморожены. Верхние блоки (`block_15`, `block_16`, `Conv_1`) пробовали дообучить один проход с learning rate 1e-5: на полном тесте Food-101 top-1 упал с 61,1% до 60,6%, поэтому эти блоки откатили. В сайте backbone и голова блюда — тот самый чекпоинт v1.

Повторный прогон официального теста Food-101, все **25 250** фото:

- top-1: **61,1%** (0,6106)
- top-5: **85,5%**

Сегментация на validation FoodSeg103, **2 135** фото, среднее IoU по 103 пищевым классам (фон в среднее не входит):

- mIoU: **13,2%**
- точность пикселя: **60,8%**

Редкие классы почти не выучились и тянут среднее вниз. Заметнее других кукуруза (IoU 54%), брокколи (54%), морковь (48%), рис (32%). Курица находится хуже риса, но на проверочном фото с рисом и курицей оба класса попали в список.

Модели в браузере — графы TensorFlow.js, веса float16: блюдо около **4,6 МБ**, ингредиенты **4,8 МБ**.

## Как переобучить

Food-101 и FoodSeg103 в git не входят.

```bash
pip install -r training/requirements.txt
# чекпоинт v1: training/train.py пишет /tmp/caloric_head.weights.h5
python training/train_seg.py --weights /tmp/caloric_head.weights.h5 --epochs 6 --finetune-epochs 1
python training/build_ingredients.py
```

Подробности по Food-101 — в [training/README.md](training/README.md). `training/train_seg.py` не даст закоммитить голову блюда, если top-1 на официальном тесте уйдёт ниже 0,6106.

## Ограничения

- 103 ингредиента FoodSeg103, не вся еда. mIoU 13% — это грубая маска: лишний класс (на фото риса с курицей вылез «картофель») и пропуски бывают часто.
- Граммы — площадь на сетке 56×56 и средняя толщина, не порция с весов.
- Название блюда показывается только при уверенности от 40%. На смешанной тарелке его часто нет, и это нормально: калории всё равно берутся из ингредиентов.
